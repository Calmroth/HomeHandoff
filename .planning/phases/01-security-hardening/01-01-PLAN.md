# Plan 1-1: Hub Authentication

**Phase:** 1 — Security Hardening
**Requirement:** SEC-01
**Estimated scope:** ~60 lines across 3 files + 1 new file

---

## Goal

`POST /command` and `POST /scan` return 401 for any request without a valid `X-Hub-Secret` header. WebSocket connections that send `command` or `scan` messages without the secret in the WS URL are rejected. Verified with `curl` from outside the app.

---

## Acceptance criteria

1. `curl -X POST http://localhost:3001/command -d '{}'` returns HTTP 401 `{"ok":false,"error":"Unauthorized"}`
2. `curl -X POST http://localhost:3001/scan` returns HTTP 401
3. `GET /health` still returns HTTP 200 (no auth required)
4. App continues to work normally (lights toggle, speaker control, LAN scan from Settings all functional)
5. `VITE_HUB_SECRET` is never printed to the console or included in any log message

---

## Implementation steps

### Step 1 — Generate the secret

Add to `.env.local` (project root and server-side both read this file via `dotenv`):

```
HUB_SECRET=<32-byte hex string>
VITE_HUB_SECRET=<same value>
```

Generate the value:
```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

`HUB_SECRET` is server-side only. `VITE_HUB_SECRET` is the same value baked into the frontend bundle — acceptable because this is a household LAN app and the secret protects against network neighbors, not the household owner reading bundle source.

### Step 2 — Create `server/lib/auth.js`

```js
import { timingSafeEqual } from 'crypto';

/**
 * Express middleware: require X-Hub-Secret header to match HUB_SECRET env var.
 * Timing-safe comparison prevents timing attacks.
 * Returns 401 if the secret is missing, wrong, or if HUB_SECRET is not configured.
 */
export function requireSecret() {
  const secret = process.env.HUB_SECRET || '';
  if (!secret) {
    console.warn('[hub:auth] HUB_SECRET not set — /command and /scan are UNPROTECTED');
  }
  const secretBuf = Buffer.from(secret);
  return (req, res, next) => {
    if (!secret) return next(); // degraded: no secret configured, warn but allow
    const provided = String(req.headers['x-hub-secret'] || '');
    let valid = false;
    try {
      valid = provided.length > 0 &&
              provided.length === secret.length &&
              timingSafeEqual(Buffer.from(provided), secretBuf);
    } catch {}
    if (!valid) return res.status(401).json({ ok: false, error: 'Unauthorized' });
    next();
  };
}

/**
 * Validate a hub secret string against HUB_SECRET.
 * Used by the WebSocket URL query-param check.
 */
export function isValidSecret(provided) {
  const secret = process.env.HUB_SECRET || '';
  if (!secret) return true; // degraded: allow all if unconfigured
  if (!provided || provided.length !== secret.length) return false;
  try {
    return timingSafeEqual(Buffer.from(provided), Buffer.from(secret));
  } catch {
    return false;
  }
}
```

### Step 3 — Apply middleware in `server/index.js`

```js
import { requireSecret, isValidSecret } from './lib/auth.js';

// After existing app.use(express.json()) and app.use(cors()):
// Apply secret check only to the two mutable endpoints
app.post('/command', requireSecret(), async (req, res) => { … });
app.post('/scan',    requireSecret(), async (req, res) => { … });
// GET /health — no change
```

### Step 4 — WebSocket auth in `server/lib/wss.js`

In `_onConnection(ws)`, extract the `secret` query param from the WebSocket's request URL and close the connection if it doesn't match:

```js
_onConnection(ws, req) {
  const url = new URL(req.url, 'ws://localhost');
  const secret = url.searchParams.get('secret') || '';
  if (!isValidSecret(secret)) {
    ws.close(4001, 'Unauthorized');
    console.warn('[hub:wss] rejected unauthenticated connection');
    return;
  }
  // … existing connection logic
}
```

The `WebSocketServer` `connection` event receives both `(ws, request)` — update the handler signature in `constructor`:
```js
this._wss.on('connection', (ws, req) => this._onConnection(ws, req));
```

### Step 5 — Update `src/lib/useWebSocketHub.js`

Append `?secret=…` to the hub URL:

```js
const secret = import.meta.env.VITE_HUB_SECRET || '';
const HUB_URL = (() => {
  const base = (typeof import.meta !== 'undefined' && import.meta.env?.VITE_HUB_URL)
    ? import.meta.env.VITE_HUB_URL
    : 'ws://localhost:3001';
  if (!secret) return base;
  const sep = base.includes('?') ? '&' : '?';
  return `${base}${sep}secret=${encodeURIComponent(secret)}`;
})();
```

### Step 6 — Update hub REST calls in `src/App.jsx` (if any)

Search for direct `fetch('…/command')` or `fetch('…/scan')` calls in App.jsx and add the header:
```js
headers: {
  'Content-Type': 'application/json',
  ...(import.meta.env.VITE_HUB_SECRET ? { 'X-Hub-Secret': import.meta.env.VITE_HUB_SECRET } : {}),
}
```

The primary command path is through the WebSocket (the secret is in the URL); REST calls are only used as fallback in dev/debug.
