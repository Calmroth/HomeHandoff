# Plan 1-2: Token Migration

**Phase:** 1 — Security Hardening
**Requirement:** SEC-02
**Estimated scope:** ~10 lines in 1 file

---

## Goal

After `migrateFromLocalStorage()` runs, the three legacy localStorage keys that contain integration tokens are deleted. `localStorage` contains no plaintext credentials. Verified with DevTools → Application → Local Storage.

---

## Acceptance criteria

1. Open DevTools → Application → Local Storage → `http://127.0.0.1:5183`
2. After app loads and migration completes, none of these keys exist in localStorage:
   - `hdg-sp-token` (Spotify OAuth tokens)
   - `hdg-g-credential` (Google ID token)
   - `hdg-integrations` (Plejd cloudSession, HA token, Tibber key, Sonos URL)
3. App continues to work after migration — credentials are read from secureStore, not localStorage
4. On a fresh browser (no prior localStorage), migration runs silently with no errors

---

## Background

`src/lib/secureStore.js` — `migrateFromLocalStorage()` (lines ~140–190):

The migration copies each key from localStorage to the AES-GCM encrypted IndexedDB store, then deliberately skips the `removeItem` calls:

```js
// Deliberately keep the legacy localStorage entries in place for
// one release cycle so an interrupted migration is recoverable.
```

This comment is from initial development. The "one release cycle" window has passed. Keeping the originals means any browser devtools inspection or XSS would still find the tokens in plaintext.

The fix is a one-line change per migrated key.

---

## Implementation

### Change in `src/lib/secureStore.js`

Locate the migration block where each source key is processed. For each key, add `localStorage.removeItem(srcKey)` immediately after the `await setSecret(destKey, value)` call succeeds.

**Before (existing pattern for each key):**
```js
try {
  const raw = localStorage.getItem(srcKey);
  if (raw) {
    await setSecret(destKey, JSON.parse(raw));
    migrated++;
  }
} catch (e) {
  errors.push({ key: srcKey, error: e.message });
}
```

**After:**
```js
try {
  const raw = localStorage.getItem(srcKey);
  if (raw) {
    await setSecret(destKey, JSON.parse(raw));
    localStorage.removeItem(srcKey); // clear plaintext original after confirmed write
    migrated++;
  }
} catch (e) {
  errors.push({ key: srcKey, error: e.message });
}
```

The `removeItem` is inside the `try` block, after `setSecret` succeeds. If `setSecret` throws, `removeItem` never runs — the plaintext original remains as the safe fallback, which is the correct behavior.

### Migration version bump

The migration function checks a version marker to skip on re-runs. Bump it from `'1'` to `'2'` so existing installs that have already run the v1 migration (which left originals in place) will run again and clean up.

```js
const MIGRATION_VERSION = '2'; // was '1'
const VERSION_KEY = 'hdg-secure-migrated';
```
