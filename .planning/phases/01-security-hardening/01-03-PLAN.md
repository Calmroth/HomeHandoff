## Plan A — SEC-03: Plejd hub proxy

### Add `/api/plejd` route to `server/index.js`

This route must be added:
- BEFORE the `requireSecret` middleware on `/command` and `/scan` (Plejd browser calls do not carry the hub secret — they originate from the Settings UI which talks to Plejd cloud, not to the hub's integration commands)
- AFTER `express.json()` (to parse any body if needed)

```js
// server/index.js — add after /health, before /command
app.use('/api/plejd', async (req, res) => {
  const upstream = `https://cloud.plejd.com${req.path}`;
  try {
    // Forward the request to cloud.plejd.com, stripping host and hop-by-hop headers
    const { host, connection, 'transfer-encoding': _te, ...forwardHeaders } = req.headers;
    const upRes = await fetch(upstream, {
      method:  req.method,
      headers: { ...forwardHeaders, host: 'cloud.plejd.com' },
      body:    ['GET', 'HEAD'].includes(req.method) ? undefined : JSON.stringify(req.body),
    });
    // Forward response status + headers (skip hop-by-hop)
    res.status(upRes.status);
    upRes.headers.forEach((v, k) => {
      if (!['transfer-encoding', 'connection', 'keep-alive'].includes(k.toLowerCase())) {
        res.setHeader(k, v);
      }
    });
    res.send(await upRes.text());
  } catch (e) {
    res.status(502).json({ ok: false, error: `Plejd proxy: ${e.message}` });
  }
});
```

No new npm dependencies — uses Node 18+ built-in `fetch`.

### No change to `src/lib/plejdCloud.js`

`BASE = '/api/plejd'` already points to the correct path. In dev, Vite proxies it. In production, the hub serves it. The client code is already correct.

## Plan B — SEC-04: Remove secret env var seeding

### Remove `VITE_TIBBER_TOKEN` seeding from `src/App.jsx`

The `seedFromEnv` effect in App.jsx (around line 1650–1683) copies VITE_* vars into integration config on mount. The Tibber token should only come from user entry in Settings, not from a baked env var.

**Remove this block:**
```js
if (env.VITE_TIBBER_TOKEN) integrations.setIntegration('tibber', { token: env.VITE_TIBBER_TOKEN });
```

The Tibber data pipeline (price, consumption) comes from the hub WebSocket via `startTibberPoller`. The browser doesn't need direct Tibber API access if the hub is running. If the hub is not running, the Tibber integration is already unavailable regardless.

### Remove `VITE_HOME_ASSISTANT_TOKEN` seeding from `src/App.jsx`

**Remove this block (lines ~1672–1676):**
```js
if (env.VITE_HOME_ASSISTANT_URL || env.VITE_HOME_ASSISTANT_TOKEN) {
  integrations.setIntegration('plejd', {
    url: env.VITE_HOME_ASSISTANT_URL || integrations.config.plejd?.url || '',
    token: env.VITE_HOME_ASSISTANT_TOKEN || integrations.config.plejd?.token || '',
  });
}
```

Note: `VITE_HOME_ASSISTANT_URL` (not the token) is still a reasonable convenience — but the token should never be in the bundle. Splitting: keep URL seeding, remove token seeding.

**Keep:**
```js
if (env.VITE_HOME_ASSISTANT_URL) {
  integrations.setIntegration('plejd', {
    url: env.VITE_HOME_ASSISTANT_URL,
    token: integrations.config.plejd?.token || '',
  });
}
```

### Update `.env.local` comments

Add a comment above `VITE_TIBBER_TOKEN` and `VITE_HOME_ASSISTANT_TOKEN` entries (if present) indicating they are deprecated and should not be set:

```
# DEPRECATED: VITE_TIBBER_TOKEN bakes the token into the JS bundle — do not set.
# Set TIBBER_TOKEN (server-only) instead.
# VITE_TIBBER_TOKEN=

# DEPRECATED: VITE_HOME_ASSISTANT_TOKEN bakes the token into the JS bundle — do not set.
# Configure the HA token via Settings → Home Assistant instead.
# VITE_HOME_ASSISTANT_TOKEN=
```
